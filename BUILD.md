# Building floppy images

The top-level `Makefile` builds bootable PC-9801 CP/M-86 floppy images without committing generated disk images to Git.

## Required tools

The normal `make` target requires:

- `make`
- `nasm`
- Python 3

HxC is optional and is only needed for HFE output.

## Required CP/M-86 core

The repository contains the PC-9801 IPL and BIOS sources, but not the Digital Research CP/M-86 CCP/BDOS binary. Before building, place the first `0x2500` bytes (9472 bytes) of the resident CP/M-86 image at:

```text
external/system/cpm86_core.bin
```

The Makefile assembles `src/cbios.asm`, pads it to its `0x1900`-byte area, and appends it to this core. The resulting resident image is exactly `0x3e00` bytes, matching the layout loaded by `src/fdipl.asm`:

```text
0000h-24ffh  CP/M-86 CCP/BDOS core (external)
2500h-3dffh  PC-9801 CBIOS (built from source)
```

If you already have a bootable RAW image made by this port, the core can be extracted from it because sector 0 is the IPL and the resident image starts at sector 1:

```sh
mkdir -p external/system
dd if=old_pc98_cpm86.img of=external/system/cpm86_core.bin \
   bs=1 skip=512 count=9472 status=none
```

`external/` is ignored by Git.

## Optional CP/M-86 commands

Any `*.CMD` files placed in:

```text
external/commands/
```

are copied into user 0 of both generated floppy images. This is the place for standard CP/M-86 commands and for locally built `FDISK.CMD`, `FDFORMAT.CMD`, and `HDFORMAT.CMD`.

The utility sources under `command/` use Digital Research ASM86/GENCMD syntax and therefore are not part of the normal Linux-hosted build. Their existing build instructions remain in `command/README.md`.

## Build

Run:

```sh
make
```

This creates:

```text
build/pc98_cpm86_2dd.img
build/pc98_cpm86_2dd.d88
build/pc98_cpm86_2hd.img
build/pc98_cpm86_2hd.d88
```

The RAW images use the native PC-98 geometries used by this port:

- 2DD: 80 cylinders, 2 heads, 8 x 512-byte sectors per side (640 KiB)
- 2HD: 80 cylinders, 2 heads, 15 x 512-byte sectors per side (1200 KiB)

`scripts/mkcpm86image.py` creates the CP/M filesystem directly, writes the generated system area, and adds optional external commands. `cpmtools` is therefore not required for the normal build.

The D88 files are generated by `scripts/raw2d88.py`, so no separate D88 converter is required.

## HFE images

If the HxC command-line converter `hxcfe` is installed, run:

```sh
make hfe
```

This creates:

```text
build/pc98_cpm86_2dd.hfe
build/pc98_cpm86_2hd.hfe
```

## Other targets

```sh
make raw          # RAW .img images only
make d88          # RAW prerequisites plus D88 images
make hfe          # D88 prerequisites plus HFE images (requires hxcfe)
make check-tools  # check normal host-side build dependencies
make check-core   # verify the external CCP/BDOS core
make clean        # remove build/
```

Generated floppy images are intentionally ignored by Git and should normally be published as release assets rather than committed to the repository.
